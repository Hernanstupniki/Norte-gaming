# Sección "Importados" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a full "Importados" (imported-on-request) commercial section to Norte Gaming — DB support for order-only availability and undefined pricing, admin controls, a reusable CTA/WhatsApp flow on the existing `ProductCard` and product detail page, a dedicated `/importados` page, a home promo block, and a navbar entry — without changing behavior for the existing catalog.

**Architecture:** One new Prisma enum (`ProductAvailability`) plus a nullable `currentPrice`, threaded through the existing NestJS DTOs/service, the existing `Category` table (no schema change — "Importados" is just a row), and the existing frontend `Product` type/mapper. All new UI reuses `ProductCard` and the existing admin form; nothing is duplicated.

**Tech Stack:** NestJS + Prisma + PostgreSQL (backend), Next.js 16 (App Router) + React 19 + Tailwind (frontend), Jest (backend unit tests — frontend has no test runner configured, verified via `next build`'s type-check).

**Spec:** `docs/superpowers/specs/2026-08-19-importados-design.md`

## Global Constraints

- Existing catalog behavior must not change: any product without `availability` set behaves exactly as `IN_STOCK` does today (spec §1, §15).
- Never render `$0` or a fabricated price — absent price always renders as the literal string "Consultar precio" (spec §12).
- "Importado" (category) and "A pedido" (availability) are separate, independent concepts — never conflate them into one field (spec, "Conceptos clave").
- WhatsApp messages are built generically from product data (name + variants) — never hardcoded per product (spec §7 / design §7).
- All new UI must reuse `ProductCard` and existing button/style conventions — no parallel card or button system (spec §16).
- Frontend has no configured test runner; the test cycle for frontend tasks is `npm run build` (runs `next build`, which type-checks) plus the manual verification steps listed in each task.

### Task 2: Backend DTOs — optional price + availability

**Files:**
- Modify: `backend/src/products/dto/create-product.dto.ts`

**Interfaces:**
- Consumes: `Prisma.ProductAvailability` enum from Task 1 (`@prisma/client`).
- Produces: `CreateProductDto.currentPrice?: number | null`, `CreateProductDto.availability?: ProductAvailability`. `UpdateProductDto` inherits both automatically via `PartialType`.

- [ ] **Step 1: Make `currentPrice` optional and add `availability`**

In `backend/src/products/dto/create-product.dto.ts`, change:

```ts
  @Type(() => Number)
  @IsNumber({ maxDecimalPlaces: 2 })
  @Min(0)
  currentPrice: number;
```

to:

```ts
  @IsOptional()
  @Type(() => Number)
  @IsNumber({ maxDecimalPlaces: 2 })
  @Min(0)
  currentPrice?: number | null;
```

The type is `number | null` (not just `number | undefined`) so the DTO can carry three distinct states end to end: key omitted (`undefined`, "leave unchanged" — only meaningful on update), explicit `null` ("clear the price"), and a number. `@IsOptional()` in class-validator skips validation for both `null` and `undefined`, so this doesn't loosen the numeric check.

Add the import at the top of the file:

```ts
import { ProductAvailability } from '@prisma/client';
```

Add this field after `isActive?: boolean;`:

```ts
  @IsOptional()
  @IsEnum(ProductAvailability)
  availability?: ProductAvailability;
```

Add `IsEnum` to the existing `class-validator` import:

```ts
import {
  ArrayMinSize,
  IsArray,
  IsBoolean,
  IsEnum,
  IsInt,
  IsNumber,
  IsOptional,
  IsString,
  MaxLength,
  Min,
  MinLength,
  ValidateNested,
} from 'class-validator';
```

```ts
import { Test } from '@nestjs/testing';
import { ProductAvailability } from '@prisma/client';
import { PrismaService } from '../prisma/prisma.service';
import { ProductsService } from './products.service';

describe('ProductsService', () => {
  let service: ProductsService;
  let prisma: {
    product: { create: jest.Mock; findFirst: jest.Mock; update: jest.Mock };
    $transaction: jest.Mock;
  };

  const baseDto = {
    name: 'MacBook Air M4',
    shortDescription: 'Notebook Apple a pedido, chip M4.',
    description: 'MacBook Air con chip M4, disponible a pedido para Argentina.',
    sku: 'MBA-M4-2026',
    stock: 0,
    brandId: 'brand-1',
    categoryId: 'category-importados',
    images: [{ url: 'https://example.com/macbook.png' }],
  };

  beforeEach(async () => {
    prisma = {
      product: {
        create: jest.fn().mockImplementation(({ data }) => Promise.resolve({ id: 'p1', ...data })),
        // `findFirst` backs two different lookups in ProductsService: the
        // update() existence check (queries by `id`) and generateUniqueSlug's
        // collision check (queries by `slug`). Route by which key is present
        // so the existence check finds the product but the slug check always
        // reports "no collision" — otherwise generateUniqueSlug loops up to
        // 1000 times against a mock that never says a slug is free.
        findFirst: jest.fn().mockImplementation(({ where }: { where: Record<string, unknown> }) =>
          Promise.resolve('id' in where ? { id: where.id } : null),
        ),
        update: jest.fn().mockImplementation(({ data }) => Promise.resolve({ id: 'p1', ...data })),
      },
      $transaction: jest.fn().mockImplementation((cb: (tx: unknown) => unknown) => cb(prisma)),
    };

    const moduleRef = await Test.createTestingModule({
      providers: [ProductsService, { provide: PrismaService, useValue: prisma }],
    }).compile();

    service = moduleRef.get(ProductsService);
  });

  it('creates a product without currentPrice as null, defaulting availability to IN_STOCK', async () => {
    const result = await service.create(baseDto as never);

    expect(prisma.product.create).toHaveBeenCalledWith(
      expect.objectContaining({
        data: expect.objectContaining({
          currentPrice: null,
          availability: ProductAvailability.IN_STOCK,
        }),
      }),
    );
    expect(result).toBeDefined();
  });

  it('creates a product with an explicit ORDER_ONLY availability', async () => {
    await service.create({
      ...baseDto,
      currentPrice: 2500000,
      availability: ProductAvailability.ORDER_ONLY,
    } as never);

    expect(prisma.product.create).toHaveBeenCalledWith(
      expect.objectContaining({
        data: expect.objectContaining({
          availability: ProductAvailability.ORDER_ONLY,
        }),
      }),
    );
  });

  it('update: omitting currentPrice leaves the existing price untouched', async () => {
    await service.update('p1', { name: 'MacBook Air M4 (renamed)' } as never);

    expect(prisma.product.update).toHaveBeenCalledWith(
      expect.objectContaining({
        data: expect.objectContaining({ currentPrice: undefined }),
      }),
    );
  });

  it('update: explicit null clears the price ("Consultar precio")', async () => {
    await service.update('p1', { currentPrice: null } as never);

    expect(prisma.product.update).toHaveBeenCalledWith(
      expect.objectContaining({
        data: expect.objectContaining({ currentPrice: null }),
      }),
    );
  });
});
```
